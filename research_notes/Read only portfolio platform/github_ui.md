# GitHub UI and software options

## Which 4-8 GitHub projects are plausible, and which are misleading fits?

### Takeaway

The strongest fit is to keep the current FastAPI service and add a small, read-only presentation layer with Chart.js; a React-admin/TanStack/Recharts frontend is the next step only if the page outgrows the current server-rendered structure. Grafana and Appsmith are credible low-code alternatives. Ghostfolio and Wealthfolio have the best ready-made portfolio experiences, but both assume their own writable transaction store and would require data duplication or a maintained fork.

### Cited Findings

- **Existing FastAPI page + Chart.js — best immediate fit.** Chart.js is an MIT-licensed, actively maintained canvas chart library; its official repository describes it as a flexible HTML5 chart library, and the latest listed release is v4.5.1. Its performance guide explicitly recommends `animation: false`, prepared/sorted data, `parsing: false`, and data decimation for large time series. This matches the request for an immediately rendered performance chart without introducing another application or database. — [Chart.js repository](https://github.com/chartjs/Chart.js); [Chart.js releases](https://github.com/chartjs/Chart.js/releases); [performance guide](https://www.chartjs.org/docs/latest/general/performance.html); [decimation guide](https://www.chartjs.org/docs/latest/configuration/decimation.html)
- **React-admin + TanStack Table + Recharts — best dedicated frontend if the UI grows.** React-admin is an MIT-licensed React/Material UI framework designed around REST or GraphQL data providers; it documents more than 50 adapters and custom adapters. Its open access-control hook can implement a `reader` role that permits only read actions. TanStack Table is an MIT-licensed headless table/grid with sorting and pagination, and Recharts is an MIT-licensed declarative React/D3 chart library. All three repositories showed current 2026 activity. — [React-admin repository](https://github.com/marmelab/react-admin); [data-provider documentation](https://github.com/marmelab/react-admin/blob/master/docs/Admin.md); [authorization documentation](https://github.com/marmelab/react-admin/blob/master/docs/Permissions.md); [TanStack Table repository](https://github.com/TanStack/table); [Recharts repository](https://github.com/recharts/recharts)
- **Grafana — credible dashboard appliance.** Grafana OSS is AGPLv3 and has built-in users, teams, Viewer/Editor/Admin roles, dashboard permissions, tables, time series, and variables. The Infinity data-source plugin can query JSON, CSV, XML, GraphQL, and HTML over HTTP, including server-side bearer-token authentication. Grafana 13.3.0 was released October 27, 2026, and Infinity reported an update on November 4, 2026. It can sit in front of FastAPI with no portfolio-specific database, but its generic observability styling will require dashboard design. — [Grafana OSS download and license](https://grafana.com/grafana/download?edition=oss); [Grafana releases](https://github.com/grafana/grafana/releases); [roles and permissions](https://grafana.com/docs/grafana/latest/administration/roles-and-permissions/); [Infinity query formats](https://grafana.com/docs/plugins/yesoreyeram-infinity-datasource/latest/query/); [Infinity installation/activity](https://grafana.com/grafana/plugins/yesoreyeram-infinity-datasource/installation/)
- **Appsmith — credible fast internal dashboard builder.** Appsmith is an Apache-2.0 internal-tool/dashboard platform that connects to REST APIs and supports tables and charts. Its REST data source supports pagination and shared authenticated API configuration; Appsmith states that it proxies queries and does not store returned source data. Default Viewer/App Viewer roles exist, while custom roles are a Business Edition feature. Version 2.6.0 was released October 28, 2026. It is faster than coding a full frontend, but it adds an entire low-code platform and produces a less portfolio-specific experience. — [Appsmith repository and license](https://github.com/appsmithorg/appsmith); [REST API documentation](https://docs.appsmith.com/connect-data/reference/rest-api); [authenticated API documentation](https://docs.appsmith.com/connect-data/reference/authenticated-api); [data-source architecture](https://docs.appsmith.com/connect-data/overview); [user roles](https://github.com/appsmithorg/appsmith-docs/blob/main/website/docs/getting-started/setup/instance-configuration/user-management.md); [releases](https://github.com/appsmithorg/appsmith/releases)
- **Ghostfolio — polished portfolio reference, weak integration fit.** Ghostfolio is an active AGPLv3 Angular/NestJS application with multi-account management, mobile-first PWA design, charts, and ROAI periods for Today, WTD, MTD, YTD, 1Y, 5Y, and Max. Its backend owns a PostgreSQL/Prisma store plus Redis, and its documented integration is a write/import API for activities. Its experimental public portfolio endpoint exposes only 1d, ytd, and max relative change. Reusing it would mean translating IBKR Flex history into Ghostfolio activities and keeping a second canonical transaction system in sync, or forking both its Angular frontend and NestJS API. — [Ghostfolio README, features, stack, and APIs](https://github.com/ghostfolio/ghostfolio/blob/main/README.md); [Docker deployment](https://github.com/ghostfolio/ghostfolio/blob/main/docker/docker-compose.yml); [AGPL license](https://github.com/ghostfolio/ghostfolio/blob/main/LICENSE); [releases](https://github.com/ghostfolio/ghostfolio/releases)
- **Wealthfolio — strongest full-application alternative if its database becomes canonical.** Wealthfolio is an active AGPLv3 local-first portfolio tracker with self-hosted Docker/web support, multiple accounts, TWR and MWR returns, benchmarks, historical analysis, portfolio reporting scopes, CSV imports, and a REST API server. Version 3.11.0 shipped October 23, 2026. It stores self-hosted data in its own SQLite database and its CSV importer creates Wealthfolio activities or holdings snapshots. Its self-hosted authentication supports a shared password or OIDC allowlists, but the documented configuration does not expose a Viewer/Editor role boundary. It is plausible only if the team is willing to import Flex data into Wealthfolio and either accept its write UI or maintain a read-only fork/perimeter. — [Wealthfolio repository](https://github.com/wealthfolio/wealthfolio); [releases](https://github.com/wealthfolio/wealthfolio/releases); [accounts and portfolios](https://wealthfolio.app/docs/guide/accounts/); [CSV import](https://wealthfolio.app/docs/guide/csv-import/); [self-hosted configuration](https://wealthfolio.app/docs/guide/self-hosting/configuration/)
- **Apache Superset — plausible after putting history in SQL.** Superset is an active Apache-2.0 Python/React BI platform. It has a granular security model and published dashboards; its Public principal is designed for read-only dashboard/chart/filter use, while Gamma has limited dataset access but can create its own charts and dashboards. Superset is SQL-dataset oriented, so the FastAPI/Flex layer would need to materialize normalized portfolio history into PostgreSQL or another supported SQL database. This is useful if the fund wants broad analyst-built BI, but too large for one portfolio page. — [Superset repository](https://github.com/apache/superset); [standard role definitions](https://github.com/apache/superset/blob/master/RESOURCES/STANDARD_ROLES.md); [security model](https://superset.apache.org/docs/security/)
- **Metabase — plausible only as a SQL-backed reporting layer.** Metabase OSS is AGPL outside its commercially licensed `enterprise` directory. It supports dashboards, collections, groups, and disabling query creation for viewers, and recommends using a dedicated read-only database user. Its supported source list is database-centric rather than a generic REST adapter. Fine-grained view permissions, row/column security, and impersonation are Pro/Enterprise features, so free OSS is acceptable when every signed-in collaborator may see the same complete portfolio but becomes costly for account-level segmentation. — [Metabase licensing](https://github.com/metabase/metabase/blob/master/LICENSE.txt); [supported databases](https://www.metabase.com/docs/latest/databases/connections); [read-only database user recommendation](https://www.metabase.com/docs/latest/databases/users-roles-privileges); [permissions tutorial](https://www.metabase.com/learn/metabase-basics/administration/permissions/data-permissions); [edition limits](https://www.metabase.com/docs/latest/permissions/data)
- **Misleading fit: Portfolio Performance.** It is actively maintained and has excellent investment analytics, but it is an Eclipse/Java desktop application, not a centrally hosted collaborative web UI; release 0.89.0 shipped desktop binaries in October 2026. Its EPL-1.0 code can be useful as a calculation reference, not as the shared presentation layer. — [Portfolio Performance GitHub organization](https://github.com/portfolio-performance); [0.89.0 release artifacts](https://github.com/portfolio-performance/portfolio/releases)
- **Misleading fit: rotki.** Rotki is active and AGPLv3, but its own documentation describes a local, privacy-focused application concentrated on crypto portfolio tracking and tax reporting. Reusing it for multi-account IBKR equities would require replacing its core asset/data model and would still not provide the desired central read-only collaboration model. — [rotki repository](https://github.com/rotki/rotki); [rotki FAQ](https://github.com/rotki/docs/blob/main/faq.md)

### Inferences

- A purpose-built portfolio application is attractive visually but creates the most integration work because the fund already has a canonical IBKR Flex archive and Python parsing path. The safest architecture keeps that source of truth and exposes computed, immutable views.
- The exact requested periods (1D, 1W, 1M, 3M, YTD, 1Y, ALL) are easier to guarantee in the existing backend than by adopting Ghostfolio, whose documented built-in periods omit 3M, or by conforming Flex data to another application's transaction model.
- Chart.js has the lowest bundle, deployment, and operating cost for the current one-file FastAPI HTML page. React-admin is justified when navigation, many resources, account-level permissions, or multiple dashboard screens appear.

### Gaps

- I found no maintained open-source portfolio web application that both consumes an arbitrary external read-only FastAPI portfolio API and ships a complete multi-user Viewer role without adopting its own transaction database.
- Neither Ghostfolio nor Wealthfolio documents native IBKR Flex XML ingestion. Both would need a custom importer and reconciliation process.

## Can these options consume an external read-only API without enabling writes?

### Takeaway

The custom Chart.js frontend, React-admin, Grafana Infinity, and Appsmith can consume FastAPI directly. Strict read-only behavior must also be enforced by the backend or the credential used by the UI; hiding buttons is not a security boundary. Superset and Metabase should receive a read-only SQL projection, while Ghostfolio and Wealthfolio expect imports into their own stores.

### Cited Findings

- React-admin's `dataProvider` is the boundary to any REST/GraphQL API, and resources expose list/create/edit/show views independently. Its access-control example shows a `reader` role permitting only read actions, so a frontend can register only list/show routes and omit all mutating methods. The documentation warns that, without `canAccess`, all pages are assumed accessible. — [data provider](https://github.com/marmelab/react-admin/blob/master/docs/Admin.md); [authorization](https://github.com/marmelab/react-admin/blob/master/docs/Permissions.md)
- Grafana's Infinity connector performs requests from the Grafana server and can store bearer-token/API-header configuration server-side. It disables PUT, PATCH, and DELETE unless an administrator enables “dangerous HTTP methods.” However, Grafana explicitly warns that a Viewer can submit arbitrary queries to any data source available in the organization, not only the queries placed on a dashboard. Therefore its FastAPI credential must be read-only and endpoints/allowed hosts must expose only safe data. — [Infinity configuration](https://grafana.com/docs/plugins/yesoreyeram-infinity-datasource/latest/configure/); [Grafana security guidance](https://grafana.com/docs/grafana/latest/setup-grafana/configure-security/)
- Appsmith's authenticated API data source supports API-key and bearer-token authentication and stores common API configuration. Appsmith can define GET-only queries, but its general REST connector also supports write methods, so read-only status depends on which queries builders create and what the backend credential permits. End users should receive App Viewer/Viewer rather than Developer access. — [authenticated API](https://docs.appsmith.com/connect-data/reference/authenticated-api); [REST methods](https://docs.appsmith.com/connect-data/reference/rest-api); [roles](https://github.com/appsmithorg/appsmith-docs/blob/main/website/docs/getting-started/setup/instance-configuration/user-management.md)
- Superset's embedded guest token is read-only, and its Public role excludes writes and SQL Lab. Superset still expects an authorized dataset/database, so an external FastAPI service is not a first-class source; a normalized SQL snapshot or history table is the clean integration. — [Superset role capability table](https://github.com/apache/superset/blob/master/SECURITY.md); [Superset security](https://superset.apache.org/docs/security/)
- Metabase recommends a dedicated database principal with minimum read privileges. Optional write features such as transforms, uploads, actions, and model persistence need separate privileges and can be omitted. This gives a strong database-level read-only boundary, but it means loading Flex-derived history into SQL. — [Metabase database privileges](https://www.metabase.com/docs/latest/databases/users-roles-privileges)
- Ghostfolio's documented public endpoint is read-only but returns a small fixed portfolio performance object. Its useful data-ingestion route is `POST /api/v1/import`, which creates activities in Ghostfolio's own database. The product also explicitly offers create, update, and delete transactions. — [Ghostfolio README and API](https://github.com/ghostfolio/ghostfolio/blob/main/README.md)
- Wealthfolio's documented CSV import converts broker rows into activities and writes them to its local/self-hosted SQLite store. OIDC and password authentication control entry, while the published configuration documents allowlists rather than per-user read/write scopes. — [CSV import](https://wealthfolio.app/docs/guide/csv-import/); [self-hosted authentication](https://wealthfolio.app/docs/guide/self-hosting/configuration/)

### Inferences

- For the first release, the browser should call only same-origin GET endpoints protected by the existing authenticated reverse proxy. Any token held by Grafana/Appsmith should be a new read-only service key, never a Flex query token or an admin/sender key.
- The backend should expose already-computed portfolio history and period-return results. This reduces client work, makes every UI show identical numbers, and prevents arbitrary historical queries from turning into expensive repeated Flex downloads.
- If all collaborators see the same portfolio, reverse-proxy authentication plus GET-only backend routes is enough. Per-account visibility later requires authorization inside FastAPI or a database view/row-security layer; UI role checks alone are insufficient.

### Gaps

- Appsmith's exact default-role matrix has changed across editions; a deployment trial should confirm that the Community Edition's App Viewer role cannot open the editor or inspect stored data-source credentials.
- Wealthfolio's current docs do not expose a supported “viewer mode” switch for the whole application.

## What are the maintenance, license, data-model, and collaboration tradeoffs?

### Takeaway

The component route has the smallest operational and licensing surface: MIT libraries inside the existing service. Full applications bring identity and collaboration features, but they also add databases, migrations, upgrades, and stronger copyleft or commercial constraints. The greatest technical risk is maintaining two independently calculated versions of portfolio history and returns.

### Cited Findings

- Chart.js, React-admin, TanStack Table, and Recharts use permissive MIT licenses. Appsmith and Superset use Apache-2.0. Grafana, Ghostfolio, Wealthfolio, and rotki use AGPLv3; Metabase combines AGPL code with a commercial-license `enterprise` directory. — [Chart.js](https://github.com/chartjs/Chart.js); [React-admin](https://github.com/marmelab/react-admin); [TanStack Table](https://github.com/TanStack/table); [Recharts](https://github.com/recharts/recharts); [Appsmith license](https://github.com/appsmithorg/appsmith/blob/release/LICENSE); [Superset](https://github.com/apache/superset); [Grafana OSS](https://grafana.com/grafana/download?edition=oss); [Ghostfolio license](https://github.com/ghostfolio/ghostfolio/blob/main/LICENSE); [Wealthfolio](https://github.com/wealthfolio/wealthfolio); [rotki](https://github.com/rotki/rotki); [Metabase license](https://github.com/metabase/metabase/blob/master/LICENSE.txt)
- Ghostfolio's deployment has three stateful/runtime services: the application, PostgreSQL, and Redis. Wealthfolio's self-hosted edition is simpler operationally, using a Docker/web app and SQLite, but it requires careful backup of the database, profile registry, encrypted vault, and master key. — [Ghostfolio Compose file](https://github.com/ghostfolio/ghostfolio/blob/main/docker/docker-compose.yml); [Wealthfolio self-hosting/backup guidance](https://github.com/wealthfolio/wealthfolio/blob/main/docs/self-host/README.md)
- Grafana has a clear Viewer role and teams, but its OSS Viewer can directly query every data source it can reach; fine-grained data-source permissions are an Enterprise feature. Superset's Public/embedded guest path is stricter for consumption, but Superset's standard Gamma role can create dashboard content on granted data. — [Grafana roles](https://grafana.com/docs/grafana/latest/administration/roles-and-permissions/); [Grafana data-source security warning](https://grafana.com/docs/grafana/latest/setup-grafana/configure-security/); [Superset capability table](https://github.com/apache/superset/blob/master/SECURITY.md)
- Metabase can prevent query creation while allowing dashboard viewing, but its OSS version lacks configurable granular View Data controls; row/column security and impersonation require Pro or Enterprise. — [Metabase permission tutorial](https://www.metabase.com/learn/metabase-basics/administration/permissions/data-permissions); [Metabase edition limits](https://www.metabase.com/docs/latest/permissions/data)
- Ghostfolio already calculates return periods and Wealthfolio calculates time-weighted and money-weighted returns. Those benefits depend on each application's activity, price, cash-flow, and account model. Import errors, transfer semantics, FX handling, or missing historical prices can therefore make their results diverge from Flex-derived results. Wealthfolio's importer documentation, for example, distinguishes deposits, transfers, and holdings snapshots because they affect returns differently. — [Ghostfolio feature list](https://github.com/ghostfolio/ghostfolio/blob/main/README.md); [Wealthfolio repository feature list](https://github.com/wealthfolio/wealthfolio); [Wealthfolio CSV semantics](https://wealthfolio.app/docs/guide/csv-import/)
- All shortlisted projects showed recent 2026 releases or repository activity: Grafana 13.3.0 on October 27, Appsmith 2.6.0 on October 28, Wealthfolio 3.11.0 on October 23, Portfolio Performance 0.89.0 on October 11, and Chart.js 4.5.1 on October 13; Superset, React-admin, Ghostfolio, TanStack Table, Recharts, Metabase, and rotki repositories also showed current activity when checked. — [Grafana releases](https://github.com/grafana/grafana/releases); [Appsmith releases](https://github.com/appsmithorg/appsmith/releases); [Wealthfolio releases](https://github.com/wealthfolio/wealthfolio/releases); [Portfolio Performance releases](https://github.com/portfolio-performance/portfolio/releases); [Chart.js releases](https://github.com/chartjs/Chart.js/releases); [Superset](https://github.com/apache/superset); [React-admin](https://github.com/marmelab/react-admin); [Ghostfolio](https://github.com/ghostfolio/ghostfolio); [TanStack Table commits](https://github.com/TanStack/table/commits); [Recharts](https://github.com/recharts/recharts); [Metabase](https://github.com/metabase/metabase); [rotki](https://github.com/rotki/rotki)

### Inferences

- Running an unmodified AGPL service alongside FastAPI is operationally reasonable, but modifying/embedding its code in a private web product creates source-offer/compliance work. MIT/Apache components keep a future proprietary deployment simpler.
- A second portfolio engine creates permanent reconciliation work: every correction to transfer, dividend, split, FX rate, or benchmark must be applied consistently in both systems. A UI that reads one returns API avoids this class of failure.
- “Collaboration” for the current read-only phase mainly means shared authentication, saved URLs/filters, and consistent numbers. It does not yet justify a collaborative BI authoring platform.

### Gaps

- This review is technical, not legal advice; AGPL obligations should be reviewed before distributing or modifying an AGPL frontend.
- No option was load-tested against the fund's actual number of accounts and daily history points.

## Which option best fits the current small FastAPI codebase?

### Takeaway

Keep the existing FastAPI application and build the smallest read-only dashboard: one precomputed portfolio-history endpoint, one period-return endpoint or combined response, and a Chart.js line chart with animations disabled. Preserve the existing table. Add reverse-proxy identity for multiple users and enforce GET-only access in FastAPI. Revisit React-admin only after the dashboard becomes a multi-page application.

### Cited Findings

- Chart.js specifically documents `animation: false` as reducing CPU usage and allowing a single render, with Path2D caching where available. It recommends supplying normalized, sorted data and decimating dense line series; its sample demonstrates 100,000 points with parsing/animation disabled and LTTB or min/max decimation. — [performance guide](https://www.chartjs.org/docs/latest/general/performance.html); [100,000-point decimation sample](https://www.chartjs.org/docs/latest/samples/advanced/data-decimation)
- Chart.js is responsive by default and supports a resize delay, so it can fit the existing responsive portfolio layout without adopting React. — [responsive chart documentation](https://www.chartjs.org/docs/latest/configuration/responsive.html)
- If a later UI rewrite is warranted, React-admin's REST data-provider boundary and independent list/show/create/edit resource registration map cleanly to FastAPI; TanStack Table supplies an advanced headless grid and Recharts supplies composable financial-performance charts without another backend. — [React-admin data provider](https://github.com/marmelab/react-admin/blob/master/docs/Admin.md); [TanStack Table](https://github.com/TanStack/table); [Recharts](https://github.com/recharts/recharts)
- Grafana remains the best no-code fallback because Infinity can consume JSON directly and the Viewer role blocks dashboard editing, but the arbitrary-query warning means its data source must point to a deliberately narrow read-only API. — [Infinity query documentation](https://grafana.com/docs/plugins/yesoreyeram-infinity-datasource/latest/query/); [Grafana roles](https://grafana.com/docs/grafana/latest/administration/roles-and-permissions/); [security warning](https://grafana.com/docs/grafana/latest/setup-grafana/configure-security/)

### Inferences

- Recommended sequence:
  1. Compute and persist one daily fund/account NAV series from the existing Flex archive; avoid querying IBKR separately for every browser request.
  2. Return the requested 1D, 1W, 1M, 3M, YTD, 1Y, and ALL values with the chart series in one cacheable GET response.
  3. Render the shell and last cached summary immediately, then fetch/replace the newest data; disable chart animation and decimate only when points exceed the display's useful resolution.
  4. Put authentication at the reverse proxy for all collaborators and keep every browser-facing backend route read-only. Use a separate read-only service credential if Grafana or Appsmith is trialed.
  5. Evaluate React-admin/TanStack/Recharts only when more portfolio screens or account-specific authorization make the current inline page hard to maintain.
- This approach preserves one calculation engine, one archive, one deployment, and one source of truth. It also addresses the animation/load complaint directly rather than replacing the entire product.
- For a two-day prototype comparison, build the same portfolio summary in the current page and Grafana. Keep Grafana only if non-developers need to compose dashboards; otherwise its extra service and generic UX do not earn their cost.

### Gaps

- The exact authentication/reverse-proxy product already deployed for the current dashboard was outside this research scope.
- Whether a single daily Flex archive contains enough values to compute correct money-weighted or time-weighted fund returns depends on the available cash-flow and NAV fields; that must be verified separately against the actual Flex query and archives.
